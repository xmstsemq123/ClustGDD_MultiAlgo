## 0. 一句話結論

- **只把 K-Means 改成「大小平衡」（Balanced K-Means）沒有用。** 在 5 個資料集上，準確率跟原版的差距都在 ±1.2 個百分點以內，大多落在誤差範圍內。
- **改成「先依類別分配名額、再在每個類別裡分群」（Class-aware K-Means）在類別多、壓縮率小的資料集明顯有效。** arXiv 0.05% 多了約 2 個百分點，Reddit 0.05% 多了約 3 個百分點，Citeseer 0.9% 多了約 3.5 個百分點，而且不同 seed 之間的結果更穩定。
- **原因是「每個類別都有分到合成節點」，不是「cluster 大小平均」。** 原版 K-Means 在 arXiv 0.05% 只讓 40 個類別中的約 26 個拿到合成節點，Class-aware 讓 40 個類別全部都有。
- **這個改法在 Cora 和 Flickr 上沒有幫助，甚至略降。** 原因的分析在[第 6.4 節](#64-為什麼-cora-和-flickr-沒有進步)。

## 1. 先複習：這篇論文在做什麼

### 1.1 問題：圖資料蒸餾（Graph Data Distillation, GDD）

我們手上有一張很大的圖 G，例如 Reddit 有 23 萬個節點、5700 萬條邊。在上面訓練 GNN 很慢。
**GDD 的目標**是把 G 壓縮成一張很小的「合成圖」G′，例如只有 76 個節點，並希望：

> 拿 G′ 訓練出來的 GNN，拿去原圖 G 上做節點分類，準確率要跟用整張 G 訓練的差不多。

所以 GDD 的**評分方式**一律是：用 G′ 訓練一個 GCN，再到**原圖的測試節點**上算準確率。

### 1.2 ClustGDD 的做法（對照程式）

ClustGDD 的核心想法是：**把原圖的節點分成 n 群，每一群合併成一個合成節點。** 完整流程如下，括號裡是程式位置：

| 步驟 | 論文 | 做了什麼 | 程式 |
|---|---|---|---|
| ① 特徵平滑 | Eq. (7) 的 **Z** | 把每個節點的特徵跟鄰居做加權平均（重複 T 次），讓相鄰節點的特徵變得相近 | `clustgdd_agent_*.py` 的 `pretrained_clustering` 前半段 |
| ② 預訓練 | Eq. (7)–(9) 的 **H = ZW** | 用訓練集的標籤訓練一個線性模型（MLP），輸出每個節點對 K 個類別的分數 **H**（N×K 的矩陣） | `model.fit_with_val(...)` |
| ③ **分群** | Eq. (6) | 對 **H** 做 K-Means，分成 n 群 C₁,…,Cₙ | `run_clustering(...)`，**我們只改這一步** |
| ④ 建立合成圖 | Eq. (11) | 合成特徵 X′ = 每群 Z 的平均；合成邊 A′ = C̃ᵀÃC̃；合成標籤 Y′ = 每群 H 平均值中分數最高的類別 | `cluster_feat_centers`、`graph_compress` |
| ⑤ CAAR 微調 | §4.2 | 對 X′ 做一點依類別的修正，緩解異質邊（heterophily）造成的過度平滑 | `graph_refusion` |
| ⑥ 評估 | §6 | 在 G′ 上訓練 2 層 GCN，到原圖測試節點上算準確率 | `test_with_val` |

**重點：** 我們只替換步驟 ③。①②④⑤⑥ 的程式和超參數都**完全沒有動**，超參數直接沿用作者提供的 `main_transduct.sh` / `main_induct.sh`。所以準確率的差異只能來自分群方法本身。

### 1.3 論文的理論依據：為什麼用分群

論文第 3 節用 **FID** 衡量 G′ 跟 G 有多像（越小越像），並證明了兩個上界：

- **Theorem 3.1：** FID 的第一項（平均值差距）≤ (1/N²)·Σᵢ (N/n − |Cᵢ|)²。
  白話：**每一群的大小越接近平均值 N/n，這個上界就越小**，也就是「群的大小越平衡越好」。
- **Theorem 3.2：** FID 的第二項（分布形狀差距）的上界跟 **WCSS** 正相關。
  白話：**每一群內部的點越集中越好**，而 K-Means 本來就是在最小化 WCSS。

不過論文在 §4.1 自己也指出一個矛盾（見論文 Fig. 2）：**如果硬性要求每群一樣大，當類別本身大小不平均時，就會把不同類別的節點塞進同一群。** 所以作者最後只用 K-Means 降低 WCSS，**沒有強制平衡**。

**我們的實驗就是從這個矛盾出發的。**

### 2.2 圖學習名詞

| 名詞 | 說明 |
|---|---|
| **Transductive（直推式）** | 訓練時看得到整張圖，包括測試節點的特徵和邊，只是看不到測試節點的標籤。Cora、Citeseer、arXiv 屬於這種，所以**全部 N 個節點都會被分群**。 |
| **Inductive（歸納式）** | 訓練時只看得到訓練節點構成的子圖，測試節點是新的。Flickr、Reddit 屬於這種，所以**只對訓練節點分群**。 |
| **壓縮率 ratio** | 論文定義：transductive 是 n/N，inductive 是 n/N_train。例如 Cora 1.3% = 35/2708。程式裡的 `--reduction_rate` 是另一套數字（n = 訓練節點數 × reduction_rate），對照見 [4.1](#41-資料集與壓縮率)。 |
| **同質性（Homophily）** | 相連的節點傾向屬於同一類。ClustGDD 的步驟 ① 就是依賴這個假設：平滑後同類節點會靠在一起，比較容易被分進同一群。 |
| **GCN** | Graph Convolutional Network，評估時用的 GNN（2 層）。 |
| **CAAR** | Class-Aware Attribute Refinement，論文 §4.2 的特徵修正模組。我們沒有改它。 |
| **Seed（隨機種子）** | 控制隨機性的數字。同一個 seed 會產生同一個 H、同一個初始分群。我們用 15、16、17 三個 seed。 |

### 2.3 分群與評估指標（`results.jsonl` 的欄位）

| 指標 | 欄位名 | 定義 | 怎麼看 |
|---|---|---|---|
| **準確率** | `acc_test_mean` | 用 G′ 訓練 GCN 5 次，在原圖測試節點上的平均準確率 | **越高越好**，是最終成績 |
| **WCSS** | `wcss` | Within-Cluster Sum of Squares：每個點到所屬群中心的距離平方，取平均（程式中除以 N） | 越小代表群內越集中。K-Means 就是在最小化這個 |
| **群大小變異係數 (CV)** | `size_cv` | 各群大小的標準差 ÷ 平均值 | 0 代表每群一樣大；越大越不平衡。是 Theorem 3.1 在意的量 |
| Theorem 3.1 上界 | `thm31_bound` | Σᵢ (N/n − \|Cᵢ\|)² / N² | 越小代表理論上 FID 第一項越小 |
| **純度 (purity)** | `purity` | 每一群中最多數的真實類別占該群的比例，再對所有節點平均 | 1 代表每一群都只含一個類別。**這裡用了真實標籤，但只拿來分析，沒有拿來訓練** |
| 標籤一致率 | `label_agreement` | 節點的真實類別跟它所屬合成節點的標籤 Y′ 一致的比例 | 越高代表合成標籤越「對」 |
| **類別覆蓋數** | `syn_classes_covered` | 合成標籤 Y′ 裡出現了幾個不同的類別 | **最大值是 K。如果小於 K，代表有些類別在 G′ 裡一個合成節點都沒有，GCN 根本學不到這些類別** |
| **FID** | `fid` | 論文 Eq. (1)：‖μ_org − μ_syn‖² + tr(Σ_org + Σ_syn − 2(Σ_org Σ_syn)^½) | 越小代表 G′ 跟 G 的分布越像。⚠️ 我們是在**預訓練的 H** 上計算（H vs. H′=C̃ᵀH），論文 Fig. 1 用的是 GCN 的 embedding，所以數值不能跟論文直接比 |
| **Spearman ρ** | `correlation.md` | 等級相關：兩個量的「排名」有多一致。+1 是完全同向，−1 是完全反向，0 是無關 | 我們每格只有 12–21 個點，**\|ρ\| 要大約 0.45–0.6 以上才算統計上顯著**（p<0.05） |

## 3. 我們的研究問題與動機

論文的理論推導（Theorem 3.1）說「群的大小平衡比較好」，但實作上只用 K-Means，沒有強制平衡。這中間有一個空隙，我們想回答三個問題：

1. **Q1：如果強制群的大小平衡，準確率會變好嗎？**
   → 設計 **Balanced K-Means**。
2. **Q2：論文擔心平衡會混雜類別。有沒有辦法同時做到平衡和類別不混雜？**
   → 設計 **Class-Balanced K-Means**：先依（預測的）類別切開，在每個類別裡面做平衡分群。
3. **Q3：真正影響準確率的是哪個性質？WCSS、群大小平衡、FID，還是類別純度？**
   → 對每個 run 記錄這些指標，計算它們跟準確率變化的相關性；再加上**對照組**（其他分群演算法）和**負對照**（隨機分群）。

為什麼這樣設計？課程要求**改進**論文方法，不只是重跑。而論文自己點出了一個沒有解決的矛盾（平衡 vs. 類別純度），這是一個有理論根據、可以檢驗的改進方向。

## 4. 實驗怎麼做

### 4.1 資料集與壓縮率

| 資料集 | 類型 | 被分群的節點數 N | 類別數 K | 合成節點數 n（三種壓縮率） | ratio（論文的寫法） |
|---|---|---|---|---|---|
| Cora | Transductive | 2,708 | 7 | 35 / 70 / 140 | 1.3% / 2.6% / 5.2% |
| Citeseer | Transductive | 3,327 | 6 | 30 / 60 / 120 | 0.9% / 1.8% / 3.6% |
| arXiv (ogbn-arxiv) | Transductive | 169,343 | 40 | 90 / 454 / 909 | 0.05% / 0.25% / 0.5% |
| Flickr | Inductive | 44,625 | 7 | 44 / 223 / 446 | 0.1% / 0.5% / 1% |
| Reddit | Inductive | 153,932 | 41 | 76 / 153 / 769 | 0.05% / 0.1% / 0.5% |

**一個重要的觀察：** arXiv 0.05% 只有 90 個合成節點，卻要表示 40 個類別，平均每個類別只有 2.25 個。Reddit 0.05% 是 76 個節點對 41 個類別，平均不到 2 個。**名額非常緊**，這一點在後面會變得很關鍵。

### 4.2 比較的分群方法

所有方法都一樣：輸入 H，輸出「剛好 n 個非空的群」。如果有空群，程式會從最大的群挑一個最遠的點補進去（`ensure_nonempty`），確保 G′ 一定有 n 個節點。

| 方法 | 角色 | 怎麼做 | 為什麼放進來 |
|---|---|---|---|
| **K-Means（論文原版）** | 基準線 (baseline) | Cora/Citeseer/Flickr 用 sklearn `KMeans`（n_init=10）；arXiv/Reddit 用 `MiniBatchKMeans`，跟原作者程式一樣 | 要打敗的對象 |
| **Balanced K-Means** | 我們的方法（驗證 Q1） | 從 K-Means 的結果出發，重複 Lloyd 迭代（指派→更新中心，最多 30 次），但**每群最多 ⌈(1+ε)N/n⌉ 個點**。指派時，「放不進最近群損失最大」的點優先選（regret 排序），滿了就換第二近的群。保留 WCSS 最小的那一次結果 | 直接檢驗 Theorem 3.1：強制平衡有沒有用 |
| **Class K-Means** | 我們的方法（消融用） | 1. 用 argmax(H) 得到每個節點的**預測類別**；2. 依各類別的節點數**按比例分配 n 個名額**，每個出現的類別至少 1 個（最大餘數法）；3. 在每個類別裡各自做 K-Means | 確保每個類別都有合成節點、每一群只含一個預測類別。用來拆開「類別分配」和「平衡」各自的效果 |
| **Class-Balanced K-Means** | **我們主要提出的方法**（回答 Q2） | 同上，但第 3 步在每個類別裡改做 Balanced K-Means。名額跟類別大小成正比，每群大小又接近該類別的平均，所以**整體上也接近 N/n**，同時滿足 Theorem 3.1 和論文 Fig. 2 的要求 | 回應論文自己提出的矛盾 |
| GMM | 對照組 | 高斯混合模型（對角共變異數） | 另一種「軟」分群，群可以是橢圓形 |
| Ward | 對照組 | 階層式聚合分群，Ward 連結 | 另一種最小化群內變異的方法。需要 O(N²) 記憶體，**只跑 Cora/Citeseer** |
| Spectral | 對照組 | 在 H 的 kNN 圖上做譜分群 | 依據「鄰近關係」而不是距離分群。同樣 O(N²)，**只跑小圖** |
| Random balanced | **負對照** | 把節點隨機打散，平均分成 n 群（CV≈0，完美平衡） | 如果「平衡」本身就夠，這個應該也不錯。實際上它應該要很差，才能證明實驗流程確實對分群品質敏感 |

> **公平性說明：** Class-aware 方法用的是**模型預測的類別**（H 的 argmax），**沒有額外使用任何真實標籤**。H 本來就是原版 ClustGDD 用訓練集標籤訓練出來的，原版在步驟 ④ 決定合成標籤 Y′ 時也一樣用了 argmax(H)。所以 Class-aware 方法沒有比原版多拿到任何資訊。

### 4.3 實驗流程與重複次數

```
對每個 (資料集, 壓縮率, 分群方法, ε, seed)：
    1. 用該 seed 跑步驟 ①② 得到 H          ← 同一個 seed 下，所有方法拿到的 H 完全相同
    2. 用指定方法分群（步驟 ③），記錄 WCSS、CV、純度、FID 等指標
    3. 跑步驟 ④⑤ 建立 G′
    4. 在 G′ 上訓練 GCN 5 次（不同初始化），取原圖測試準確率的平均 → 這就是一筆 acc_test_mean
    5. 把參數、指標、準確率寫成 results.jsonl 的一行
```

- **Seed：** 15、16、17。表格中的 `平均 ± 標準差` 是**這 3 個 seed 的結果**之間的平均和標準差。
  ⚠️ 論文表格的 ± 比較可能是同一張 G′ 上重複訓練 GCN 的標準差。我們的標準差還包含了「換 seed 會得到不同 H 和不同 G′」的變異，所以通常比論文的大。
- **ε 消融實驗：** 在 Cora/Citeseer 上，對 Balanced 和 Class-Balanced 兩種方法把 ε 設為 0、0.1、0.3、0.5、1.0。ε=0 是幾乎完全平均；ε=1.0 時每群上限是平均大小的兩倍，大小分布已經跟 K-Means 差不多（CV 0.46 vs. K-Means 0.47）。所以這組實驗涵蓋了「完全平衡」到「幾乎不限制」整個範圍。
- **總共 450 個 run，全部成功：**
  - Cora、Citeseer 各 144 個 = 3 壓縮率 × 8 方法 × 3 seed（72 個）＋ ε 消融（72 個）
  - arXiv、Flickr、Reddit 各 54 個 = 3 壓縮率 × 6 方法 × 3 seed（沒有 Ward/Spectral）
- **配對比較：** 不同 seed 的 H 不同，WCSS、FID 的絕對值不能跨 seed 比較。所以分析相關性時，每個 run 都跟**同一個 seed 的 K-Means run** 相比：
  - `rel_wcss` = 本方法的 WCSS ÷ K-Means 的 WCSS
  - `d_size_cv`、`d_purity` = 本方法的值 − K-Means 的值
  - Δacc = 本方法的準確率 − K-Means 的準確率

## 6. 數據代表什麼

### 6.1 Q1 的答案：只強制平衡，沒有用

- 在 5 個資料集、15 個設定中，Balanced K-Means 跟 K-Means 的差距介於 −1.2 和 +1.2 pp 之間，大多在一個標準差以內。
- **Theorem 3.1 確實成立：** Balanced K-Means 的 CV 幾乎是 0，FID 也通常比 K-Means 低（例如 Reddit 0.05%：151 → 44）。**但準確率沒有因此提高。**
- 原因可以從 arXiv 0.05% 看出來：Balanced 的純度從 0.590 降到 0.577，類別覆蓋從 25.7 降到 22.7。這正是論文 Fig. 2 擔心的情況：大的類別被硬切成很多份，小的類別被併進別人的群，消失了。
- ε 消融也支持這個結論：平衡程度改變很大，準確率不動。

**結論：** Theorem 3.1 給的是 FID 的**上界**。把上界壓低，不代表準確率會提高。「平衡」不是 ClustGDD 準確率的瓶頸。

### 6.2 Q2 的答案：「先依類別分配，再分群」在名額緊的時候有效

- 進步最明顯的三個設定（arXiv 0.05%、Reddit 0.05%、Citeseer 0.9%）都是**壓縮率最小**的設定，其中兩個是**類別數最多**的資料集。
- **機制是類別覆蓋：** K-Means 只看距離，大類別的點多，會吃掉大部分的群中心。在 arXiv 0.05%，40 個類別中平均只有 25.7 個拿到合成節點，代表**約 14 個類別在 G′ 裡完全沒有代表**。GCN 在訓練時從來沒看過這些類別的標籤，測試時自然不可能預測對。Class-aware 方法保證每個類別至少有 1 個合成節點，所以覆蓋率變成 40/40。
- **進步幅度隨壓縮率變大而縮小**，也符合這個解釋：名額變多之後，K-Means 自己也能覆蓋大部分類別（arXiv 0.5% 時已經覆蓋 36/40），Class-aware 能補的空間就變小了。
- **穩定性：** Class-aware 方法在這幾個設定的標準差都只有 0.1～0.3，K-Means 是 0.8～2.9。原因是名額分配是確定性的，不會因為 seed 不同而有時漏掉某些類別。
- **Class vs. Class-Balanced 幾乎一樣**（差距 ≤ 0.5 pp）。這再次說明，真正起作用的是「按類別分配」，類別內部的平衡是次要的。

### 6.3 Q3 的答案：純度和覆蓋率才是關鍵，群大小和 FID 不是

- 在 arXiv 和 Reddit 上，**純度的變化跟準確率的變化高度正相關**（ρ = 0.74、0.80）。群大小 CV 則接近無關（ρ = 0.23、0.06）。
- **FID 跟準確率是弱負相關**（FID 越低、準確率越高，方向正確），但不穩定。最明顯的反例：Class K-Means 在 arXiv 0.05% 的 FID（41.3）比 K-Means（28.1）還高，準確率卻高了 1.9 pp。所以在這個設定下，**FID 不是可靠的準確率指標**，跟論文 Fig. 1 的觀察不完全一致。不過要注意，我們的 FID 是在預訓練的 H 上算的，跟論文的算法不同（見 2.3）。
- **WCSS 跟準確率幾乎無關**（Reddit 甚至是 −0.44：WCSS 越大準確率越高）。原因是 Class-aware 方法必須在類別邊界切開，WCSS 會變大，但純度提高了。

### 6.4 為什麼 Cora 和 Flickr 沒有進步

- **Cora、Citeseer（類別少、名額相對多）：** 原版 K-Means 已經覆蓋全部類別，Class-aware 的主要優勢不存在。Cora 上 Class-aware 大多略降（6 個數字中有 5 個是負的，最多 −1.5 pp）。
  一個合理的推測：照預測類別硬切時，**預測錯的節點會被鎖在錯誤的類別裡**，而 K-Means 還有機會把邊界附近的點放到更合適的群。這個推測還沒有驗證。
  Citeseer 0.9% 的 +3.4 pp 有一大部分來自「穩定」：K-Means 在 seed 16 只有 66.7%（另外兩個 seed 是 71.1% 和 72.2%），Class-aware 的三個 seed 都在 73.3～74.0%。
- **Flickr：** 預訓練 MLP 在 Flickr 的**訓練集**準確率只有約 48%（在 Reddit 是約 95%），所以 argmax(H) 給的預測類別本身就很不準。
  Class-aware 把類別覆蓋從 2.3 提高到 6.7，但多出來的那些類別大多是錯誤的預測，所以沒有幫助。
  另外，Flickr 上所有方法都落在 46～47%。隨機分群的合成標籤只剩一個類別（等於全部猜同一類），也有 42.3%。這個資料集對分群方法本來就不敏感，跟論文 Table 3 的情況一樣（所有 GDD 方法都在 46～47%）。

### 6.5 對照組與負對照

- **隨機平衡分群**的準確率大幅下降（Reddit 0.05% 只有 4.4%，Cora 34%）。它的群大小 CV 是 0，是「最平衡」的方法，但結果最差。這證明了兩件事：第一，**光是平衡沒有意義**；第二，我們的實驗流程確實對分群品質敏感，不是任何分群都能得到差不多的分數。
- **GMM** 在大部分設定都比 K-Means 差，而且不穩定（Citeseer 0.9%：66.6 ± 6.9）。它會產生大小極不平均的群（CV 常 > 0.5），FID 也最高（Reddit 0.5% 的三個 seed 都在 16,000～18,600 之間，K-Means 約 211）。
- **Ward、Spectral**（只跑小圖）跟 K-Means 差不多。Spectral 在 Cora 2.6% 和 5.2% 最好（81.0、81.6），但領先幅度在誤差範圍內。

## 7. 限制與注意事項

報告時要誠實說明以下幾點：

1. **每個設定只有 3 個 seed。** Cora、Citeseer 的很多差距都在一個標準差以內，不能宣稱顯著。最有說服力的結果是 arXiv 0.05% 和 Reddit 0.05%：差距是標準差的好幾倍，而且三個 seed 都同方向。如果時間允許，建議在這兩個設定把 seed 補到 5～10 個。
2. **重現的 baseline 比論文低 0.2～2.3 pp**（見 4.4）。我們的結論是「在相同環境下比較」，不是「打敗論文的數字」。
3. **沒有重新調參。** 所有方法都沿用作者為 K-Means 調好的超參數，這對新方法其實比較不利。
4. **FID 的計算對象跟論文不同**（H vs. GCN embedding）。
5. **Ward、Spectral 只在小圖上跑**，因為需要 O(N²) 的記憶體（N > 20,000 就跳過）。
6. **Cora 上 Class-aware 略降的原因**（6.4 的推測）還沒有用實驗驗證。

| 為什麼不直接用 FID 當指標？ | 我們發現 FID 跟準確率的相關性弱且不穩定，而且有明顯反例（見 6.3）。這本身就是一個發現。 |
| 為什麼你們的 baseline 比論文低？ | 硬體需要換 torch 版本，seed 和統計方式也不同。所有比較都在相同環境下進行（見 4.4）。 |
| 3 個 seed 夠嗎？ | 對小差距不夠，我們沒有宣稱它們顯著。主要結論（arXiv 0.05%、Reddit 0.05%、Citeseer 0.9%）的差距是 2～3.4 pp，遠大於 Class-aware 的標準差（0.1～0.3），而且**三個 seed 個別比較都是 Class-aware 勝出**（例如 arXiv：64.4→65.5、63.0→65.5、63.0→65.7）。 |
| 為什麼 Flickr 沒用？ | 預訓練模型在 Flickr 的準確率只有約 48%，預測的類別本身不可靠；而且所有 GDD 方法在 Flickr 都只有 46～47%（見 6.4）。 |
| 這個方法有什麼代價？ | 分群時間：在 arXiv/Reddit 上，K-Means 約 0.5 秒，Class K-Means 約 1 秒，Class-Balanced 約 7～9 秒，Balanced 約 12～16 秒；相對於整個流程（每個 run 需要數分鐘）可以忽略。缺點是在類別少、模型預測不準的資料集上沒有好處。 |

## 10. 檔案對照與如何重現

| 檔案 | 內容 |
|---|---|
| `results.jsonl` | 450 個 run 的原始紀錄，一行一個 run：所有參數、分群指標、每次 GCN 的準確率 |
| `summary_acc.md` / `.csv` | 準確率主表（5.1 節的來源） |
| `summary_metrics.csv` | 各設定的分群指標平均 |
| `correlation.md` | 分壓縮率的 Spearman 相關係數 |
| `figs/*.png` | 第 9 節的四張圖 |
| `smoke.jsonl` | 正式實驗前的冒煙測試，不列入分析 |

| 程式（在上一層資料夾） | 功能 |
|---|---|
| `clustering.py` | **所有分群方法和分群指標的實作**，我們的主要貢獻 |
| `run_experiments.py` | 實驗排程：跑哪些組合、用哪組作者的超參數；已經跑完的會自動跳過 |
| `run_overnight.sh` | 我們實際跑的實驗佇列 |
| `analyze.py` | 從 `results.jsonl` 產生表格和圖 |
| `clustgdd_agent_transduct.py` / `_induct.py` | 原作者的 ClustGDD 主程式。我們只把分群那一行換成 `run_clustering(...)`，並加入指標紀錄 |

重現方式（conda 環境 `clustgdd`）：

```bash
# 跑實驗（可中斷，重跑會從中斷處繼續）
python run_experiments.py --datasets cora citeseer
python run_experiments.py --datasets cora --methods balanced_kmeans --eps 0 0.1 0.3 0.5 1.0
# 產生表格與圖
python analyze.py
```
